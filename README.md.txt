# 多用户专属 AI Agent 助手（全栈 AIGC 应用）

本项目属于对赛道 A 的 AI 升级版应用，基于大模型、RAG、数据库持久化构建。

## 🚀 主要功能
- **多话题与多用户独立记忆**：左侧边栏可新建/切换/删除历史话题，基于 SQLite 隔离，互不干扰。
- **RAG 知识库检索**：接入 ChromaDB，结合私有文档准确回答，杜绝幻觉。
- **实时工具调用**：接入高德 API，AI 能自主判断并调用接口查询天气。
- **流畅体验**：基于 FastAPI 和原生 JS 实现 SSE 流式“打字机”输出。

## 💻 本地启动步骤
1. 安装依赖：`pip install -r requirements.txt`
2. 配置环境变量：复制 `.env.example` 为 `.env`，填入你的 `OPENAI_API_KEY` (DeepSeek) 和 `AMAP_API_KEY` (高德)。
3. 构建本地向量库：运行 `python test_chroma.py` （将 `test.txt` 的内容切块并存入 Chroma）。
4. 启动服务：`uvicorn main:app --reload`
5. 浏览器访问：`http://127.0.0.1:8000/webui`

## 🧪 自测结果说明
- **流程验证**：输入“公司愿景”，能检索文档并流式回答；输入“杭州天气”，能触发天气接口并总结。
- **状态验证**：切换不同用户和话题，记忆完全隔离；点击删除话题，网页和数据库同步清空。
- **已知问题**：本地运行加载 `sentence-transformers` 模型时，首次会因下载模型耗时较长（已配置国内镜像加速）。

## 📝 协同复盘（约 200 字）
在本次项目开发中，AI 是我强大的结对伙伴。前期 AI 帮我理清了 RAG 和 Function Calling 的底层数据流转逻辑，快速生成了 FastAPI 和前端 UI 的基础框架。但我并没有直接把 AI 的回答当成正确答案，而是通过不断报错、查阅文档来验证。
例如：在实现流式输出结合数据库保存时，发现如果直接 `db.close()` 会导致数据丢失，于是我和 AI 讨论后，将数据库连接的开启和关闭放到了生成器函数内部，完美解决了异步阻塞问题。在这个过程中，我学会了如何用精确的 Prompt 约束 AI 的错误行为，也深刻理解了后端数据流的生命周期。
